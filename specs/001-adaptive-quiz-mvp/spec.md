# Spec 001 — Adaptive quiz (MVP)

- Status: Approved (2026-11-17), NFR-3 amended and approved (2026-11-17)
- Date: 2026-11-17
- Constitution: 1.0.0

This document describes **what** the adaptive quiz does and **why**. It contains no technical choices: those belong in `plan.md`, written once this spec is approved.

## 1. Summary

A visitor picks a topic (JavaScript or React) and takes a 10-question quiz generated by AI. The quiz adapts as they answer: questions get harder or easier depending on their answers, and concepts they got wrong come back later in the session. Questions are single-choice, multiple-choice, or code exercises solved in an in-browser code editor. After each question the visitor sees the correction and an explanation. At the end, a summary shows their score, the level they reached and the concepts to review.

## 2. Goals

- Let anyone, developer or not, understand the app and complete a session in about ten minutes, without instructions.
- Give developers a useful way to practise JavaScript and React at their own level.
- Demonstrate adaptive learning: the visitor should *notice* that the quiz reacts to their answers.

## 3. Users

| User | Context | What they need |
| --- | --- | --- |
| **Evaluator** | Reviewing the project. Limited time, possibly not a developer. | Understand the app at a glance, finish a session quickly, see that it works reliably. |
| **Developer learner** | Wants to practise JavaScript or React. | Questions at the right level, clear explanations, real coding exercises. |

## 4. Session flow

1. The visitor chooses a topic: **JavaScript** or **React**.
2. The quiz starts at a medium difficulty level.
3. The visitor answers 10 questions, one at a time. 2 or 3 of them are code exercises.
4. After each answer, the visitor sees the correction, then moves on to the next question.
5. After the 10th question, the visitor sees the session summary and can start a new session.

## 5. User stories and acceptance criteria

Acceptance criteria are numbered so that each one can be linked to a test (constitution, principle VI).

### US-1 — Start a quiz (P1)

*As a visitor, I want to pick a topic and start right away, so that I can try the app without any setup.*

- **AC-1.1** Given the home page, when it loads, then it shows the available topics (JavaScript, React), a one-sentence description of the app, and a notice that questions are generated by AI and may contain mistakes.
- **AC-1.2** Given the home page, when the visitor selects a topic and starts, then the first question is shown, with a loading indicator while it is being prepared.
- **AC-1.3** Given a session in progress, then the visitor always sees the topic, the question number out of 10, and the current difficulty level.

### US-2 — Answer a single-choice or multiple-choice question (P1)

*As a visitor, I want to answer quickly by selecting options, so that the quiz keeps a good pace.*

- **AC-2.1** Given a single-choice question, then it offers 4 options with exactly one correct answer, and the visitor can select only one.
- **AC-2.2** Given a multiple-choice question, then it states explicitly that several answers may be correct ("Select all that apply"), it offers 4 to 6 options with at least two correct, and the visitor can select several.
- **AC-2.3** Given any question, when no option is selected, then the answer cannot be submitted.
- **AC-2.4** Given a multiple-choice question, when the visitor submits, then the answer is correct only if the selection matches exactly the set of correct options.
- **AC-2.5** Questions may include a code snippet (for example "What does this code log?"). Snippets are displayed with syntax highlighting.

### US-3 — Solve a code exercise (P1)

*As a developer, I want to write real code, so that the quiz tests what I can do and not only what I recognise.*

- **AC-3.1** Given a code exercise, then it shows a problem statement, starter code in a code editor with syntax highlighting, and a description of what the tests check.
- **AC-3.2** Given a code exercise, when the visitor clicks "Run tests", then each test is run against their code and shown as passed or failed, with the reason when it fails. The visitor can run the tests as many times as they want before submitting.
- **AC-3.3** Given a code exercise, when the visitor submits, then the answer is correct only if all tests pass. Submission is final.
- **AC-3.4** Given code that never finishes (for example an infinite loop), when the tests run, then they stop after a few seconds with a clear message, and the page stays responsive.
- **AC-3.5** The visitor's code runs isolated from the page: it cannot read or change anything outside the exercise.
- **AC-3.6** Every code exercise is solvable: before being shown, its tests are confirmed to pass against a reference solution.
- **AC-3.7** React code exercises cover logic that runs without rendering: reducers, state-update functions, selectors and other pure functions used in React apps. They never render components or call hooks.

### US-4 — Difficulty adapts to my answers (P1)

*As a visitor, I want the questions to match my level, so that the quiz is neither boring nor discouraging.*

- **AC-4.1** Difficulty uses 5 levels, from 1 (beginner) to 5 (expert). Sessions start at level 3.
- **AC-4.2** Given a correct answer, then the next question is one level harder (at most 5).
- **AC-4.3** Given an incorrect answer, then the next question is one level easier (at least 1).
- **AC-4.4** Given a level change, then the visitor is told about it (for example "Level up: 4/5").
- **AC-4.5** The level is computed from the visitor's answers by fixed rules, never decided by the AI, so the same answers always lead to the same levels.

### US-5 — Missed concepts come back (P2)

*As a learner, I want to get another chance on what I got wrong, so that I actually learn it.*

- **AC-5.1** Every question is tagged with one concept of its topic (for example *closures*, *promises*, *useEffect*).
- **AC-5.2** Given an incorrect answer on a concept, then a later question in the same session targets that concept again, from a different angle, as long as questions remain.
- **AC-5.3** No two questions in a session are identical or near-identical.

### US-6 — Get feedback after each question (P1)

*As a learner, I want to understand my mistakes right away, so that every question teaches me something.*

- **AC-6.1** Given a submitted single-choice or multiple-choice answer, then the visitor sees whether it was correct, the correct options, and a short explanation.
- **AC-6.2** Given a submitted code exercise, then the visitor sees the test results, a reference solution, and a short review of their code written by the AI (correctness, readability, idiomatic use of the language).
- **AC-6.3** The AI review never changes the verdict: only the tests decide whether a code answer is correct.
- **AC-6.4** Given the feedback screen, when the visitor clicks "Next question", then the next question is shown.

### US-7 — See my session summary (P1)

*As a visitor, I want a summary at the end, so that I know where I stand and what to work on.*

- **AC-7.1** Given the 10th answer, then the summary shows the score (correct answers out of 10), the level reached, and how the level evolved over the session.
- **AC-7.2** The summary lists the concepts mastered and the concepts to review.
- **AC-7.3** Given the summary, the visitor can start a new session on the same topic or on another one.

### US-8 — Things go wrong gracefully (P1)

*As a visitor, I want clear messages when something fails, so that I never face a broken page.*

- **AC-8.1** Given the AI service is unavailable or too slow, then the visitor sees a clear message and can retry the same step without losing their progress.
- **AC-8.2** Given the visitor has reached the usage limit, then they see a message explaining that the demo is limited and when they can try again.
- **AC-8.3** Given the project's monthly AI budget is used up, then the visitor sees a message explaining that the demo is temporarily unavailable.
- **AC-8.4** Error messages never show technical details (stack traces, upstream errors).

## 6. Non-functional requirements

- **NFR-1 Responsiveness.** A loading indicator appears within 200 ms of any action that waits for the AI. A new question is usually ready within 5 seconds.
- **NFR-2 Accessibility.** WCAG 2.2 level AA (constitution, principle VIII). The whole quiz, code editor included, can be used with a keyboard only, and keyboard focus can always leave the code editor.
- **NFR-3 Bounded cost.** A session triggers a bounded number of AI requests: at most two per question generated (the second only when the first output fails validation), plus one review per code exercise submitted. The summary needs no AI request.
- **NFR-4 Usage limit.** A single visitor can start only a limited number of sessions per hour. The exact limit is set in the plan.
- **NFR-5 Content quality.** Questions stay on the chosen topic, are technically correct, and single-choice questions have exactly one defensible answer. Generated content that does not have the expected structure is never shown to the visitor.
- **NFR-6 Language.** The interface and all generated content are in English.
- **NFR-7 Desktop first.** The MVP targets desktop browsers. Phone layouts are out of scope.

## 7. Out of scope for the MVP

- User accounts, saved history, progress across visits
- Free-text topics, topics other than JavaScript and React
- Free-text answers judged by AI
- React code exercises that render components or call hooks
- Timers, leaderboards, sharing results
- Languages other than English
- Phone layouts
- The e-learning module generator (a future spec)

## 8. Assumptions

These product choices were made to complete the spec and confirmed by the project owner on 2026-11-17.

1. **Starting level.** Every session starts at level 3 out of 5. Visitors do not choose their starting level.
2. **No partial credit.** A multiple-choice answer is correct only if it is exactly right. A code answer is correct only if every test passes.
3. **One level at a time.** Each answer moves the level by exactly one step.
4. **Code exercises.** 2 or 3 per session, never two in a row. Their difficulty follows the current level like any other question.
5. **No skip.** The visitor must answer each question. "I don't know" is not an option.
6. **Reload.** Reloading the page during a session may lose the session. Resuming is out of scope for the MVP.

## 9. Resolved questions

- **Retry on invalid AI output** (resolved 2026-11-17, during planning). NFR-3 originally allowed one AI request per question. It now allows a second request when the first output fails validation, so that a malformed or unsolvable question is replaced without the visitor seeing an error. See decision D4 in `plan.md`.
- **React code exercises** (resolved 2026-11-17). Exercises stay on logic that runs without rendering (AC-3.7). Rendering and testing components is more realistic for React, but it makes running code in the browser significantly more complex. It is a candidate for a later spec.
